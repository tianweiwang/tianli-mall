# 天俪加盟门店平台 H5 Demo

这是与 CRMEB 正式商城隔离的静态演示应用。消费者端、门店端和品牌方后台共享浏览器本地演示状态，不连接 API、数据库、真实支付或微信授权。

## 环境要求

- Node.js 22 LTS（最低 Node.js 20.19）
- npm 10 或更高版本
- Chromium、Chrome 或 Edge 最新稳定版

## 本地运行

```powershell
npm install
npm run dev
```

默认开发地址为 `http://127.0.0.1:4173/#/c/store/TL1001`。

## 测试与构建

```powershell
npm run test
npm run build
npm run preview
npm run test:e2e
```

生产预览默认为 `http://127.0.0.1:4174/#/c/store/TL1001`。`dist/` 是唯一需要部署的目录，构建产物使用相对资源路径和 hash 路由。

## 主演示顺序

1. 从门店入口码进入天俪锦江店。
2. 打开商品详情，加入购物车并提交订单。
3. 完成模拟支付，记录新订单号。
4. 返回首页创建到店预约，展示真实核销二维码和备用编号。
5. 通过演示导航切换到门店端，在“扫码核销”中扫描二维码、上传二维码图片或输入备用编号。
6. 确认核销后返回门店工作台，查看预约和到店率变化。
7. 切换到品牌方后台，在“全平台订单”中查找刚创建的订单。
8. 在“分账流水”中打开对应记录并推进模拟分账状态。

### 区域代理结算演示

品牌方按“区域代理 → 归属门店 → 门店核销特色/经典项目 → 会员本金结算 → 分账流水 → 代理待结转已结 → 分销管理查看独立推广预算”的顺序演示。积分项目显示非现金结算，集团直营门店使用门店 50%、集团 50% 模板。

所有支付和分账均为当前浏览器中的本地模拟。正式上线必须读取并校验微信实际获批的最大分账比例 `max_ratio`。
9. 打开演示导航，二次确认“重置演示数据”，返回默认消费者门店首页。

设备检测演示：消费者预约 -> 门店检测中心 -> 模拟设备回传 -> 生成报告 -> 消费者前后对比 -> 复评预约 -> 品牌检测运营。

本 Demo 不连接真实检测设备，不执行医疗诊断，设备结果、影像、指标变化和效果统计均为固定演示数据。

演示状态统一保存在浏览器的 `tianli.franchise-demo.v1` 中。不同设备之间不会实时同步；扫描设备可根据有效核销码导入一条明确标记的本机演示记录。
