# 品牌服务与商品目录管理 Demo 设计

## 背景

当前品牌方“目录管理”页面已经展示服务项目和实物商品，但只支持筛选与查看详情。门店端和消费者端直接读取完整的 `services`、`products` 数组，因此品牌方无法演示新增、编辑、上下架或按门店投放目录，也无法证明总店修改后其他端会同步变化。

本变更把品牌方目录页补成可操作的本地 Demo，同时继续保持静态 H5、无接口、无数据库的边界。

## 目标

- 品牌方统一维护服务项目和实物商品。
- 品牌方可新增、编辑、上下架并选择适用门店。
- 门店端保持只读，只看到当前门店适用且已上架的目录。
- 消费者端按当前门店展示已上架目录，详情、加购和结算遵循同一规则。
- 所有修改通过现有 `demoStore` 持久化到浏览器 `localStorage`，重置后恢复固定示例数据。

## 不包含

- 删除目录项。
- 图片文件上传、对象存储或素材库。
- 门店自主定价、自建商品、独立库存或自主发货。
- 服务排班、技师排班或自动生成预约时段。
- 真实接口、数据库、账号权限或审核流。
- 修改 CRMEB 正式商城代码。

## 角色边界

### 品牌方

品牌方菜单“目录管理”调整为“服务与商品”，仍使用 `/brand/products` 路由。页面保留服务项目和实物商品双 Tab，并增加新增、编辑、上架、下架操作。

### 门店端

门店端“服务与商品”继续只读。页面只展示当前 `activeStoreId` 适用且已上架的项目与商品，不提供维护按钮。

### 消费者端

消费者分类、详情和购买入口只读取当前路由门店适用且已上架的目录。已下架或不适用于当前门店的详情地址显示“已下架或当前门店不可用”。

## 数据模型

### 公共字段

服务项目和实物商品增加以下字段：

- `status`: `active` 或 `inactive`。
- `storeIds`: 适用门店 ID 数组，至少选择一家营业门店。
- `createdAt`、`updatedAt`: 使用固定的 `demoNow`，用于演示详情和排序。

现有商品的 `selling` 状态迁移为 `active`。所有初始目录默认适用于两家营业门店，不包含停用门店。

### 服务项目

可维护字段为名称、系列、说明、服务时长、价格模式、单次价、疗程价、疗程数量、疗程单位和适用门店。

标准定价必须有正数单次价；疗程可不填写，填写时疗程价和数量必须同时为正数。定制报价只保留正数起价，不保存疗程字段。新增服务不自动生成预约时段，因此消费者端显示“暂未开放线上预约，可到店咨询”。

### 实物商品

可维护字段为名称、系列、分类、单位、规格、统一售价、划线价、集团库存、配送类型、图片地址和适用门店。

名称、分类、单位、至少一个规格、正数售价和适用门店为必填项。库存不得为负数。新增商品未填写图片地址时复用 Demo 内置默认商品图，不增加上传功能。

### 标识与版本

新增目录项使用独立的服务和商品序列生成稳定 ID，不复用订单序列。`DEMO_VERSION` 升级，旧浏览器状态按现有机制恢复为新版固定示例数据，避免旧对象缺字段导致不同页面口径不一致。

## 领域逻辑

新增独立的目录领域模块，负责：

- 校验和规范化表单输入。
- 新增服务与商品。
- 更新允许维护的字段，不改变 ID、销量或历史引用。
- 切换上下架状态。
- 判断目录项是否对指定门店可见。

页面不直接拼装或修改目录对象。所有状态变更仍通过 `demoStore.commit()` 写入，保证单次提交、持久化和重置行为一致。

## 三端联动

选择器提供按门店过滤后的服务和商品集合，消费者分类页、消费者详情页和门店目录页统一复用。

- 上架且 `storeIds` 包含当前门店：消费者和门店可见。
- 下架：品牌方仍可见，消费者和门店不可见。
- 不适用于当前门店：该门店及其消费者不可见，其他适用门店正常可见。
- 品牌方新增或编辑后，同一浏览器切换角色即可看到最新状态。

现有预约时段不会因服务下架而删除，历史预约继续按快照和 `serviceId` 展示。服务恢复上架后原有有效时段重新可见。

## 购物车与下单

加入购物车时再次确认商品对当前门店可售。结算创建订单时也执行同一校验，防止商品加入购物车后被下架或移出适用门店仍可付款。

校验失败时阻止下单并提示“商品已下架或当前门店不可售”。历史订单保存创建时的商品名称、图片、价格和规格，不随目录修改而变化。

## 页面交互

品牌目录页使用现有后台表格和 Element UI 对话框：

- 页面右上角提供“新增服务项目”或“新增商品”主按钮。
- 每行提供“查看”“编辑”以及“上架/下架”操作。
- 表格增加状态和适用门店列。
- 新增与编辑复用同一个表单对话框，提交成功后关闭并显示成功提示。
- 上下架需要二次确认；不提供删除入口。
- 表单校验失败时保留输入并显示明确字段错误。

不引入新的 UI 框架，不改变品牌后台整体导航和视觉主题。

## 异常与边界

- 至少选择一家当前营业门店；停用门店不出现在新建表单可选项中。
- 编辑已有目录时保留已关联但后来停用的门店标识，用户主动保存时只能选择营业门店。
- 重复名称允许存在，ID 保持唯一；名称不承担业务主键职责。
- 商品库存为零仍可展示，但禁止加入购物车和下单。
- 下架或移出门店范围不会改写历史订单、预约、分账或结算记录。
- 表单金额统一转换为整数分保存，页面输入和展示使用元。

## 测试策略

### 领域单元测试

- 新增、编辑、上下架服务与商品。
- 必填字段、金额、库存、规格和适用门店校验。
- 唯一 ID 生成和不可变字段保护。
- 按状态与门店过滤目录。
- 旧购物车商品在下架或移出门店后无法创建订单。

### 页面单元测试

- 品牌页显示新增、编辑、上下架入口并提交到领域模块。
- 门店页只读且只展示本店可用目录。
- 消费者分类和详情按门店、状态过滤。
- 新增服务无排班时显示到店咨询。

### 浏览器验收

1. 品牌方新增一个仅适用于锦江店的服务并上架。
2. 切换锦江店消费者端可见该服务，滨江店不可见。
3. 品牌方下架该服务后，消费者与门店端均不再显示。
4. 品牌方编辑一个商品并限制适用门店，消费者商品列表同步变化。
5. 将购物车内商品下架后尝试结算，页面明确拦截。
6. 重置演示数据后，新增内容消失并恢复固定示例目录。

最后运行完整 Vitest、生产构建、相关 Playwright、`git diff --check` 和 OpenSpec 校验。

## 实施范围

改动限定在独立 H5 Demo 的种子数据、目录领域模块、选择器、品牌目录页、消费者目录/详情/购物车下单链路、门店只读目录、测试、说明文档和对应 OpenSpec 变更。当前工作区其他会员、分销、检测、区域代理功能不做重构。
