# Apache-2.0 许可一致性与外部授权解耦设计

**日期：** 2026-07-30

**状态：** 已确认，待 OpenSpec 与实施计划

## 1. 背景

仓库根目录 `LICENSE` 使用 Apache License 2.0，`README.md` 明确声明代码可免费商用、无隐藏费用或功能限制。但当前源码、安装器和管理端仍保留专有商业许可约束、商业授权联网查询以及域名授权提示，形成相互冲突的许可表达和运行行为。

本设计以仓库根目录 Apache-2.0 许可证为项目代码的唯一许可依据，在保留适用版权和作者归属的前提下，移除专有商业许可限制与主动授权联网。CRMEB 官方在线升级被视为独立外部服务：默认关闭，不绕过其服务端鉴权，显式启用后才允许联网。

## 2. 已确认方案

采用“许可一致性清理”方案：

1. 清理与 Apache-2.0 冲突的专有许可文本。
2. 删除 CRMEB 商业授权查询、申请、购买和后台首页自动验权链路。
3. 保留本地版权配置、系统环境信息、本地升级、备份和回滚能力。
4. 将 CRMEB 官方在线升级改为默认关闭的可选外部服务。
5. 删除安装完成后的站点信息上报。
6. 不删除短信、支付、物流、云存储等由用户主动配置的第三方业务集成。

未采用以下方案：

- 仅修改源码头部：仍会留下安装器专有协议、商业授权页面和主动联网，不满足目标。
- 删除全部 CRMEB 或第三方服务：会破坏与软件许可无关的可选业务能力，范围过大。

## 3. 目标与非目标

### 3.1 目标

- 自有源码只表达 Apache-2.0 许可，不再声明“不是自由软件”或必须购买商用授权。
- 新安装流程不要求商业授权、唯一域名、授权码或强制展示 CRMEB 链接。
- 后台首页、系统信息页和安装完成页不再向 CRMEB 授权或商城服务主动发送站点信息。
- 商业授权查询和申请接口从前后端及新装数据库元数据中移除。
- 官方远程升级在默认配置下不建立任何外部连接。
- 商品、订单、用户、支付、示例数据及现有业务配置保持不变。

### 3.2 非目标

- 不删除或改写 `vendor/` 中第三方组件的许可证和版权声明。
- 不删除 CRMEB 原始著作权和作者归属；Apache-2.0 第 4 条要求分发源码时保留适用声明。
- 不破解、模拟或绕过 CRMEB 官方升级服务器的鉴权。
- 不承诺 CRMEB 官方托管服务、升级包、短信或技术支持免费。
- 不做商城品牌全面更名；本次只移除强制版权兜底和商业授权相关展示。

## 4. 当前冲突面

### 4.1 源码头部

1242 个已跟踪自有源码文件包含以下限制性声明：

```text
Licensed CRMEB并不是自由软件，未经许可不能去掉CRMEB相关版权
```

这些文件分布在后端应用、项目框架代码、管理端、uni-app、配置、安装和升级代码中。版权、官网来源和作者行不属于本次删除范围。

### 4.2 专有许可文件与安装协议

以下内容与根 Apache-2.0 许可证直接冲突：

- `crmeb/LICENSE.txt`
- `help/resource/LICENSE.txt`
- `crmeb/public/install/templates/step1.php` 内嵌软件许可协议

它们包含购买商用许可、绑定唯一域名、不得修改或重新分发、不得删除底部链接、可终止使用许可等限制。

### 4.3 商业授权联网链路

当前链路包括：

- 后端授权查询与申请：`Common::auth`、`Common::auth_apply`、`SystemAuthServices`。
- 后端路由：`check_auth`、`auth`、`auth_apply`。
- 管理端 API：`auth`、`authApply` 以及只服务于授权购买的远程商品调用。
- 后台首页挂载时自动查询授权，失败后静默忽略。
- 系统信息页中残留的商业授权、验证码、购买 iframe、授权状态和授权码逻辑。
- 新装 SQL 中的验证授权、申请授权和授权信息接口元数据。

### 4.4 站点信息上报

`crmeb/public/install/templates/step5.php` 在安装完成后向 CRMEB 服务发送站点域名、URL、版本、平台、推广标识和 IP 等信息。该请求不是完成本地安装的必要步骤。

### 4.5 官方在线升级

`UpgradeServices` 会使用当前域名与 `.version` 中的应用标识登录 CRMEB 升级服务，并在域名未授权时拒绝官方在线升级。该限制属于外部升级服务，而不是商城核心运行许可。

## 5. 详细设计

### 5.1 统一许可表达

对已跟踪的自有源码执行精确机械替换：

```text
Licensed CRMEB并不是自由软件，未经许可不能去掉CRMEB相关版权
```

替换为：

```text
Licensed under the Apache License, Version 2.0
```

替换只匹配完整限制行，不重写整段文件头，不改变文件编码、换行或其他代码。处理范围排除 `vendor/`、`node_modules/`、`.git/`、`.codegraph/`、`.codex/`、`.worktrees/` 和编译产物。

保留：

- `Copyright (c) ...` 行。
- `Author: CRMEB Team ...` 行。
- 根目录 Apache-2.0 `LICENSE`。
- 第三方组件各自的许可和 NOTICE 文件。

### 5.2 替换专有许可文件和安装协议

`crmeb/LICENSE.txt` 与 `help/resource/LICENSE.txt` 改为 Apache-2.0 一致文本，并明确完整法律条款以仓库根 `LICENSE` 为准。

安装第一步保留“阅读并同意”交互，但展示内容改为 Apache-2.0 告知，包含：

- 允许商业使用、复制、修改和分发。
- 分发时保留适用版权、专利、商标和归属声明。
- 修改文件需标注修改。
- 软件按原样提供，不附带担保。
- 商标权和外部托管服务不由 Apache-2.0 自动授予。
- 完整条款指向随项目分发的 `LICENSE`。

安装器不再展示或要求接受专有商业许可条款。

### 5.3 删除商业授权功能

后端删除：

- `SystemAuthServices`。
- `Common::auth` 和 `Common::auth_apply`。
- `check_auth`、`auth`、`auth_apply` 路由。
- 因上述删除产生的未使用导入。

管理端删除：

- 后台首页的授权 API 导入、挂载调用和授权状态字段。
- 商业授权查询与申请 API。
- 系统信息页中的商业授权对话框、验证码、授权码、价格、购买、支付和 CRMEB 商城 iframe 逻辑。
- 只被上述流程使用的依赖、状态和方法。

系统信息页继续保留：

- 环境与目录权限检查。
- 版本信息。
- 本地可配置的版权文字与版权图片。

页面和路由名称统一为“系统信息”，不再使用“商业授权”。

### 5.4 保留中立的版权配置

现有 `GET /copyright` 与 `POST /copyright` 继续用于读取和保存站点自己的版权文字、图片。路由说明改为中立的“读取版权信息”和“保存版权信息”。

管理端、客服端和商城端只显示已配置的站点版权；配置为空时不再回退到 CRMEB 官网链接、CRMEB 支持图片或其他强制品牌展示。源码中的原始版权归属不受影响。

### 5.5 官方远程升级改为显式选择

在 `config/upgrade.php` 增加默认关闭的开关：

```text
UPGRADE_REMOTE_ENABLED=false
```

应用通过 `Env::get('upgrade.remote_enabled', false)` 读取该值。

默认关闭时：

- `UpgradeServices` 构造过程不登录升级服务器、不生成远程令牌。
- 新增本地 `GET /system/upgrade/capability`，固定返回 `status=200` 和 `data.remote_enabled` 布尔值，该接口不实例化远程客户端。
- 远程升级列表、协议、状态、包下载和日志上报在发起 HTTP 前统一返回业务 `status=400` 和“官方在线升级服务未启用”。
- 管理端在线升级页先调用本地能力接口；关闭时显示禁用状态，不继续请求远程升级接口。
- 本地跨版本升级、数据库备份、项目备份和回滚不依赖远程授权，继续可用。

显式启用时：

- 所有升级地址从 `config/upgrade.php` 读取，不再使用类内硬编码地址。
- 只允许 HTTPS 地址。
- 保留 CRMEB 官方服务端现有域名鉴权，不尝试绕过。
- 只有管理员主动进入或执行在线升级操作时才联网。

### 5.6 删除安装完成上报

删除安装完成页向 `shop.crmeb.net` 发送站点信息的脚本和相关无用变量。安装成功页面只进行本地跳转与展示，不产生外部请求。

### 5.7 新装数据与现有数据清理

新装 SQL 删除：

- 验证授权、申请授权、授权信息接口元数据。
- 只服务于商业授权流程的多语言记录。
- 任何指向已删除授权接口的权限或文档记录。

现有环境提供一个幂等清理脚本，只按精确标识删除：

- `cert_crmeb` 配置记录。
- 已删除授权接口对应的接口元数据和多语言记录。
- Redis 中的 `upgrade_auth_token`；只在远程升级关闭时清理。

清理脚本不得修改商品、订单、用户、支付、上传文件、首页装修或示例数据。执行前后沿用现有数据库快照恢复流程验证业务数据不变。

### 5.8 构建产物

管理端源码修改完成后运行现有生产构建，更新实际由 `crmeb/public/admin` 提供的静态产物。禁止直接编辑压缩后的构建文件。

## 6. 运行流程

### 6.1 后台首页

调整前：后台首页挂载 -> 本地 `auth` 接口 -> CRMEB 授权服务器 -> 忽略失败。

调整后：后台首页挂载 -> 仅加载本地统计数据，不产生 CRMEB 授权请求。

### 6.2 系统信息页

调整前：环境信息 + 商业授权查询/购买 + CRMEB iframe。

调整后：环境信息 + 本地版权配置，不加载 CRMEB 授权或商城资源。

### 6.3 官方在线升级

调整前：构造升级服务即尝试远程登录，域名未授权时报错。

调整后：先读取本地开关；默认关闭时不联网，显式启用后才进入官方登录和鉴权流程。

## 7. 错误处理

- 已删除的授权路由返回标准 404，不保留兼容代理。
- 远程升级关闭时返回稳定的业务错误码和“官方在线升级服务未启用”消息，不伪装为网络故障。
- 显式启用但配置了非 HTTPS 地址时拒绝启动远程请求，并记录管理日志。
- 远程服务不可用只影响官方在线升级，不影响后台首页、系统信息、商品、订单或商城前台。
- 版权配置为空是合法状态，不触发默认 CRMEB 品牌回退。

## 8. 验证与验收

### 8.1 静态检查

- 自有已跟踪源码中限制性头声明命中数为 0。
- 专有 EULA 中“购买商用许可”“唯一域名”“不得修改/分发”“终止使用许可”等冲突语句命中数为 0。
- `authorize.crmeb.net`、`auth_cert_query`、`auth_apply` 和 `cert_crmeb` 在运行代码及新装数据中命中数为 0。
- 保留的 Copyright、Author、根 `LICENSE` 和第三方许可证未被删除。
- 构建产物不再包含商业授权页面文案或授权 API 地址。

### 8.2 后端检查

- 所有修改 PHP 文件通过 `php -l`。
- 商业授权路由不可访问，版权配置路由仍正常工作。
- 默认配置下访问后台首页、系统信息页、本地跨版本升级状态不访问 CRMEB 域名。
- 远程升级关闭时返回稳定禁用响应；显式启用的隔离测试只使用 HTTPS 并保留服务端鉴权。

### 8.3 前端检查

- 管理端生产构建成功。
- 后台首页、系统信息页无授权请求、授权弹窗或 CRMEB 商城 iframe。
- 自定义版权保存后在管理端和商城端正确显示；空版权不显示 CRMEB 兜底。
- 页面刷新、直接访问系统信息和本地升级页面均无控制台错误。

### 8.4 数据检查

- 清理脚本可重复执行，第二次执行不报错且不产生额外变化。
- 清理前后的商品、订单、用户和示例数据计数一致。
- 数据库与 Redis 按现有验收流程恢复到验证前状态。

### 8.5 规范检查

- 为本设计创建独立 OpenSpec change。
- `openspec validate align-apache-license-and-disable-vendor-auth` 通过。
- OpenSpec、实现、构建产物和实际运行行为一致。

## 9. 风险与控制

| 风险 | 控制措施 |
| --- | --- |
| 批量替换造成无关格式变化 | 仅做完整字节串替换，检查 `git diff --numstat` 与抽样编码 |
| 误删第三方许可证 | 严格排除依赖和生成目录，并验证第三方 LICENSE/NOTICE 数量 |
| 系统信息页功能被一并删除 | 只移除商业授权状态与购买逻辑，保留环境和版权配置 |
| 默认关闭升级影响本地维护 | 将远程升级与本地跨版本升级解耦并分别验证 |
| 清理脚本破坏业务数据 | 只按精确键值删除，执行前后比较业务表与示例数据 |
| 静态源码已改但运行仍使用旧构建 | 必须完成管理端生产构建和浏览器网络验证 |

## 10. 交付边界

本次交付完成后，商城核心运行不依赖 CRMEB 商业授权服务器；项目代码的许可表达与根 Apache-2.0 许可证一致；官方在线升级仍是可选择、受其服务条款约束的外部能力。

这是一项代码和配置的一致性改造，不构成对上游权利争议的法律裁决。生产商用及品牌使用仍应由项目方结合实际分发方式进行法律审查。
