# 固定门店设备与品牌检测记录明细设计

**日期：** 2026-07-31

**状态：** 已确认，待书面审阅

## 1. 背景与目标

当前 H5 Demo 将检测设备设计成“扫码领取任务”：门店创建任务后先进入“待设备领取”，页面展示任务二维码，再由设备领取后开始检测。实际业务中，检测设备是固定放置并绑定到门店的资产，不存在顾客或门店人员领取设备、设备扫码领取任务的过程。

品牌方“检测运营”页目前只有趋势、门店质量和指标均值，无法查看某一份已发布报告的顾客、门店、设备和四项具体检测指标，也无法查看与上次、首次检测的变化。

本次目标是让 Demo 与实际业务一致，并让甲方能完整演示：

```text
门店创建检测任务
  -> 自动绑定本店在线固定设备
  -> 待检测
  -> 检测中
  -> 设备回传
  -> 待确认
  -> 门店确认并发布报告
  -> 品牌方查看脱敏检测记录和具体指标
```

## 2. 已确认决策

1. 检测设备是固定绑定到门店的资产，不需要领取设备或领取任务。
2. 创建检测任务时自动绑定该门店的在线固定设备。
3. 正常状态流为“待检测 -> 检测中 -> 待确认 -> 已完成”。
4. 删除检测任务二维码、“设备领取任务”按钮及“待设备领取/已领取”用户可见状态。
5. 保留离线重试、数据不完整、重复回传和跨店结果隔离四类异常演示。
6. 品牌方可查看顾客姓名和脱敏手机号，例如“陈女士 138****2046”。
7. 品牌方检测记录采用“表格 + 右侧详情抽屉”。
8. 品牌方不显示完整手机号、检测影像、指标编辑能力或医疗结论。

## 3. 范围边界

### 3.1 包含

- 调整本地检测任务的设备绑定与状态流。
- 调整门店检测列表和任务详情中的状态、动作及文案。
- 在品牌“检测运营”页增加已发布检测记录表、筛选和详情抽屉。
- 保留现有两份历史报告，并补充另一家门店的确定性已发布报告。
- 递增 Demo 状态版本，使旧浏览器状态自动恢复为新种子。
- 补充状态机、聚合选择器、隐私展示、页面交互和完整演示链路测试。

### 3.2 不包含

- 不接入真实检测设备、厂商 API、远程 Mock API、数据库或 CRMEB 正式业务接口。
- 不实现多设备调度、设备排队、远程控制、设备配置或校准操作。
- 不修改消费者预约核销二维码及其扫码流程。
- 不向品牌方开放原始影像、完整手机号、指标修改、报告修改或医疗诊断结论。
- 不新增算法分析、医学参考范围或真实效果宣称。

## 4. 固定设备任务流

### 4.1 自动绑定

创建预约检测任务或现场顾客检测任务时，转换层先完成现有的顾客、门店、预约和授权校验，再从该门店绑定的设备中查找状态为 `online` 的固定设备。

本次 Demo 的种子保证每个可创建检测任务的门店最多只有一台在线固定设备，因此不引入多设备选择或调度规则。找到设备后，任务在创建时直接写入 `deviceId`，初始状态为 `ready`，界面显示“待检测”。

门店没有在线固定设备时，创建动作失败并提示“本店检测设备当前不可用”，不得留下未绑定设备的检测任务。预约创建任务和现场建档入口都遵守这一规则。

### 4.2 正常状态

内部状态和用户可见文案固定为：

| 内部状态 | 门店文案 | 进入条件 |
| --- | --- | --- |
| `ready` | 待检测 | 任务创建且已自动绑定在线设备 |
| `measuring` | 检测中 | 门店点击“开始检测” |
| `awaiting-review` | 待确认 | 固定设备回传完整且匹配的载荷 |
| `completed` | 已完成 | 门店确认结果并生成正式报告 |

原 `waiting-device`、`claimed` 状态及 `claimAssessmentTask` 领取动作不再属于检测 Demo。现有历史已完成任务继续保留 `completed`。

### 4.3 门店任务详情

任务详情直接显示自动绑定的固定设备名称、型号、软件版本和在线状态，不再显示检测任务二维码。

操作区按状态提供：

- `ready`：显示“开始检测”。
- `measuring`：显示异常场景选择和“模拟设备回传”。
- `retrying`：显示“恢复并重试”。
- `awaiting-review`：显示“确认并生成报告”。
- `review-required`：显示缺失项目和重新回传入口。
- `completed`：显示报告已发布结果，不再提供状态推进操作。

活动记录删除“设备已领取任务”，任务创建记录表达为“检测任务已创建并绑定本店设备”。

## 5. 异常处理

异常仍在同一任务和自动绑定的固定设备上下文中处理：

| 场景 | 处理规则 |
| --- | --- |
| 检测中设备离线 | 任务进入 `retrying`，保留原任务、设备和尝试记录；恢复后回到 `measuring` |
| 数据不完整 | 原始提交标记为需复核，任务进入 `review-required`；补充后使用同一任务重新回传 |
| 重复回传 | 按设备结果流水去重，返回已接收结果，不新增报告 |
| 跨店设备结果 | 原始提交进入隔离状态，不改变任务归属，不生成品牌正式检测记录 |

设备在任务创建后失去连接时，不重新创建或重新绑定任务。门店通过“恢复并重试”继续同一个任务，避免产生重复顾客记录和报告。

## 6. 品牌检测记录明细

### 6.1 表格位置与数据口径

在现有“检测完成趋势”下方增加“检测记录明细”，保留现有门店质量和指标均值区域。

表格只以 `reportStatus === 'published'` 的检测报告为正式记录来源。待确认或数据不完整任务继续计入现有“待复核”运营指标，但不出现在正式记录表中。

### 6.2 筛选

表格提供三类本地筛选：

- 门店：默认全部门店。
- 检测日期：默认全部日期，可选择单日。
- 关键词：匹配报告编号或顾客姓名，不匹配完整手机号。

筛选只影响检测记录表，不改变页面顶部运营指标、趋势、门店质量和指标均值的全局统计口径。

### 6.3 表格字段

| 字段 | 展示规则 |
| --- | --- |
| 报告编号 | 已发布报告 ID |
| 顾客 | 姓名与脱敏手机号 |
| 门店 | 报告所属门店名称 |
| 固定设备 | 设备名称或型号 |
| 检测时间 | 报告 `measuredAt` |
| 肩高差 | 数值与 `mm` 单位 |
| 骨盆倾斜 | 数值与角度单位 |
| 颈前倾角 | 数值与角度单位 |
| 不适评分 | 数值与 `/10` 单位 |
| 操作 | “查看”打开右侧抽屉 |

顾客手机号统一经过选择器脱敏。无论种子中保存的是原始手机号还是已脱敏展示值，品牌页面都不得输出连续 11 位手机号。

### 6.4 右侧详情抽屉

抽屉标题显示报告编号，正文展示：

- 顾客姓名、脱敏手机号、门店和检测时间。
- 当前肩高差、骨盆倾斜、颈前倾角和不适评分。
- 每项指标相对上次报告的差值。
- 每项指标相对首次报告的差值。
- 固定设备名称、型号和软件版本。
- 报告版本。
- 已发布的非医疗建议文案。

差值复用现有检测对比规则。没有上次或首次可比较报告时明确显示“暂无对比”，不得用 `0` 冒充真实变化。

抽屉不展示检测影像，不提供下载、编辑、确认、重发或删除操作。

## 7. 演示数据与状态恢复

保留现有两份报告及其数值：

| 报告 | 肩高差 | 骨盆倾斜 | 颈前倾角 | 不适评分 |
| --- | ---: | ---: | ---: | ---: |
| `ASR202607301001` | 12 mm | 3.8 度 | 18 度 | 6/10 |
| `ASR202607301002` | 8 mm | 2.9 度 | 15 度 | 4/10 |

新增另一家门店的确定性顾客、已完成任务和已发布报告，使品牌页面初次打开即可验证跨店筛选和具体指标。新增数据使用中性、真实的演示业务信息，不包含真实客户信息或工具来源信息。

所有待处理种子任务在创建时即包含 `deviceId`，不再包含 `waiting-device` 或 `claimed`。递增 `DEMO_VERSION` 后，旧的本地存储状态按现有恢复机制自动替换为新种子；一键重置仍恢复同一批示例数据。

## 8. 代码边界

实施保持现有检测领域分层，不引入新的状态管理或通用框架：

- `assessmentFixtures.js`：固定设备、任务和报告种子。
- `assessmentTransitions.js`：自动绑定、正常状态推进和异常恢复。
- `assessmentSelectors.js`：门店任务展示、品牌已发布记录、脱敏和对比数据。
- `store/Assessments.vue`、`store/AssessmentDetail.vue`、`store/Dashboard.vue`：门店状态与动作。
- `brand/AssessmentAnalytics.vue`：检测记录表、筛选和详情抽屉。
- `seed.js`：演示状态版本和序列。
- 现有检测单元测试与 Playwright 流程测试：按新状态流更新并增加覆盖。

不修改公共二维码编解码器和预约核销二维码组件。只有检测任务详情中的领取二维码被移除。

## 9. 验证与验收

### 9.1 单元测试

- 创建任务时自动绑定本店在线固定设备，状态为 `ready`。
- 门店没有在线固定设备时创建失败，且不留下部分检测任务。
- 正常状态严格按 `ready -> measuring -> awaiting-review -> completed` 推进。
- 设备离线后在同一任务、同一设备上恢复重试。
- 数据不完整、重复回传和跨店回传不生成无效或重复报告。
- 品牌正式记录只包含已发布报告。
- 品牌记录包含门店、设备、四项具体指标和报告版本。
- 顾客手机号始终脱敏，不输出连续 11 位手机号。
- 相对上次和首次的指标差值正确；无历史时返回无对比状态。
- Demo 版本升级后旧状态恢复为确定性新种子。

### 9.2 页面与完整流程

Playwright 覆盖完整主流程：

```text
创建任务
  -> 验证自动绑定固定设备
  -> 开始检测
  -> 模拟完整回传
  -> 确认报告
  -> 打开品牌检测运营
  -> 筛选并查看新报告的具体指标和对比
```

同时验证：

- 门店页不再出现检测任务二维码、“设备领取任务”“待设备领取”或“已领取”。
- 品牌表格的门店、日期和关键词筛选可用。
- 点击“查看”打开正确报告的右侧抽屉。
- 品牌页不显示完整手机号和检测影像。
- 预约核销二维码流程继续通过原有测试。
- 桌面视口下表格、筛选栏和抽屉无重叠、横向页面溢出或文字遮挡。
