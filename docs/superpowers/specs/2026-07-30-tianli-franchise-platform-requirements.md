# 天俪商城 加盟门店平台 总体需求

**状态：** 草案，待业务确认。本文是产品蓝图，不是可直接实施的变更；每一期的落地由独立的 OpenSpec change 承载。

**日期：** 2026-07-30

---

## 1. 业务目标

把当前的单商户商城，改造成品牌方招募加盟门店、每个门店拥有独立子商城的平台。

三条核心业务规则（已确认）：

| 规则 | 内容 |
| --- | --- |
| 下单主体 | **消费者**在门店子商城下单，不是门店向集团订货 |
| 商品与库存 | **集团统一商品库**，门店不能自建商品；集团统一配送 |
| 资金流向 | 货款**先进门店自己的微信子商户号**，再分账抽成给品牌方 |
| 分销佣金 | 由**品牌方**承担，不从门店收入中扣 |
| 顾客入口 | **店内扫码**进入对应门店的子商城 |
| 线上预约 | **先预约、到店付款**；只按时段，不指定服务人员 |

这个组合有一个重要含义：因为门店不持货、不发货、不自建商品，**不需要完整的多商户架构**。多商户版最重的三块——按店独立库存、订单拆单、商家自主上架——都用不上。

### 2.3 现存缺陷（阻塞后续开发）

PHP 8.2 迁移后仍有业务功能损坏，由 `harden-runtime-acceptance` 跟踪（17/24）：

| 缺陷 | 症状 |
| --- | --- |
| `app\dao\diy\DiyDao` 缺 `getDiyInfo` 方法 | `/api/diy/get_diy` 返回 `status=400`，**首页装修数据取不到** |
| `DiyServices.php:309` `foreach()` 收到 null | 首页商品模块异常 |
| `think-orm` `Builder.php:379` `strpos()` 类型错误 | ORM 层 |
| `xaboy/form-builder` `CustomComponent::jsonSerialize()` 返回类型 | **后台设置页打不开** |

**这四项必须先修完。** 在首页装修取不到数据、后台设置进不去的系统上，无法验证任何新功能。

## 3. 三套归属的边界（关键设计决策）

改造后一笔订单会同时携带三个互不干扰的归属维度：

| 维度 | 字段 | 判定依据 | 用途 | 现状 |
| --- | --- | --- | --- | --- |
| **门店归属** | `store_mer_id`（新增） | 本次扫码入口（会话） | 资金进哪个子商户号、抽成 | 待开发 |
| 一级分销 | `spread_uid` | 谁分享的 | `one_brokerage` | **现成，不改** |
| 二级分销 | `spread_two_uid` | 分享链上级 | `two_brokerage` | **现成，不改** |

**规则：资金归属看扫码入口，分销佣金看分享链，两者独立不互相覆盖。**

**必须新增 `store_mer_id`，不能复用 `division_id`。** 原因是 `division_id` 语义为「用户永久归属的区域代理」，来源是用户表继承，顾客一旦从 A 店进入就永久锁定；而门店归属必须允许同一顾客本月贡献 A 店、下月贡献 B 店。混用会导致门店抽成与代理佣金争抢同一字段，账目算乱。

**门店主体也不复用 `eb_user` 的代理字段**——门店是企业主体，需要营业执照、对公账户、子商户号，与个人推广者语义不同。

## 4. 资金流设计

```
消费者付 100 元
  ↓ 全额进入门店 A 的微信子商户号（待分账，冻结）
  ↓ 分账：抽成 20 元 → 品牌方商户号
  ↓ 完结分账：剩余 80 元解冻 → 门店 A 可结算 → T+1 到门店对公账户
  ↓ 品牌方从抽成中支付分销佣金给分享者（走现有 eb_user_extract 提现）
```

**分销佣金不进微信分账链路**，由品牌方在拿到抽成后用现有佣金提现体系发放。这样规避了两个硬限制：分账接收方必须预先注册，以及分账总额上限。

**注意**：抽成比例必须覆盖分销成本与平台运营成本。

## 5. 分期规划

依赖关系决定顺序，不是按重要性。

### 第 0 期：修复现存缺陷（阻塞项）

`harden-runtime-acceptance`，剩余 7 项。修完 §2.3 的四个业务缺陷，让系统真正可用。

**这一期不完成，后面全部无法验证。**

### 第 1 期：线上预约

`add-store-booking`，已完成方案设计（40 项任务）。

- 不碰支付，不依赖服务商资质，可与第 3 期并行等待审批
- 复用现有核销码与门店核销员
- **技术要点**：容量占位必须用带守卫的单条更新。现有 `BaseDao::decStockIncSales()` 是先查后写（548 行 `find()`、550 行 `dec()`，`WHERE` 无数量守卫），并发会超卖，预约不可照抄
- 前置：需先确认五条业务规则（可预约天数、取消/改约规则、失约处理、单用户限额、时段由谁配）

### 第 2 期：门店主体与归属机制

- 新增 `eb_store_merchant`（门店名、执照、法人、`sub_mchid`、进件状态、抽成比例、结算账户）
- 订单新增 `store_mer_id`、`store_sub_mchid`、`brand_commission`
- 门店专属小程序码（复用 `appCodeUnlimitService`，基本现成）
- 扫码归属会话：写入 Redis 会话 → 下单时固化到订单，**不从用户表取**
- 门店只读业绩报表

**待定的边界规则**（不定清楚运营时必出纠纷）：

| 场景 | 需要决定 |
| --- | --- |
| 无门店参数直接进入（历史打开、搜索） | 取最近会话？会话过期归品牌方自营？ |
| 购物车跨店 | 按门店隔离，还是结算时以当前门店为准？ |
| 会话有效期 | 建议 7–15 天。太短丢复购归属，太长会抢其他店客户 |
| 分享传播 | 建议：保留分享者 `spread_uid`，门店归属跟随接收者入口 |

即使暂不做分账，这一期也能配合现有「记账 + 提现」模式先上线。

### 第 3 期：微信服务商与分账（最重）

**非技术前提，任一不通过方案就要重做：**

1. 品牌方能否申请微信支付服务商资质，并单独开通「服务商分账」产品权限
2. 抽成比例是否在微信分账上限内（标准为订单金额 30%，部分行业可申请提高）
3. 加盟门店是否**都有独立营业执照与对公账户**（无独立主体无法进件）
4. 税务模型经会计师确认——资金进门店主体意味着门店按全额收入开票纳税，品牌方按抽成向门店开服务费票，与现行模式完全不同

**开发内容：**

| 模块 | 量级 |
| --- | --- |
| 门店进件（API 或平台人工）与 `sub_mchid` 存储 | 小 |
| 支付参数按门店取值（改 `MiniProgramService`/`WechatService`/`v3pay` 配置注入链路） | 中 |
| 支付回调按门店密钥验签路由 | 中 |
| **微信分账 API**（接收方注册/绑定、发起、查询、完结） | **大，全新** |
| **退款与分账回退联动**（含部分退款按比例回退） | **中到大，易错** |
| 分账规则引擎与流水对账 | 中到大 |

**时间窗口约束**：分账必须在微信规定窗口内发起（默认 30 天），超时资金自动全额结算给门店，抽成收不回。

### 第 4 期：微信卡包（可选，需先确认政策）

CRMEB 未对接微信卡券，需从零开发。**建议先确认微信当前政策**——卡券会员卡能力近年在收缩，很多功能已迁移至小程序会员体系。

## 6. 全局风险

**无第一方测试套件，而第 3 期动的是资金。** 这是最大的风险。强烈建议在第 3 期开工前，至少补齐下单、支付、退款、分账、库存扣减的自动化测试。资金链路出错的代价是真金白银，且对账问题往往在事后才发现。

**验收不能只看传输层。** 已有教训：PHP 8.2 迁移曾以「HTTP 200 + 进程 RUNNING + 日志无 Fatal」判定完成，但实际首页白屏、商品列表为空——JSON 里 `status=400` 而 HTTP 是 200。所有后续验收必须断言业务状态码。

**进程 RUNNING 不等于稳定。** 同一次迁移中 Supervisor 报告四个程序全部 `RUNNING`，而 Workerman 子进程崩溃重启了 20734 次（`startsecs=3` 容忍快速重启循环）。必须断言重启计数。

**lint 工具会静默漏报。** `find | xargs php -l` 在首个致命错误处中止整批，曾把 25 处解析失败报成 1 处。必须逐文件 lint。

**遗留安全阻塞项**（与本需求并行，上线前必须处理）：24 条依赖安全公告涉及 9 个包；`guzzle/guzzle` 与 `topthink/think-factory` 已废弃，`overtrue/wechat` 3.x 停止维护；TLS、生产密钥、备份恢复演练均未配置。

## 7. 待确认清单

开工前需业务方决定：

**预约（第 1 期）**
1. 可提前几天预约？当天能约吗？
2. 开始前多久可取消？可改约几次？
3. 失约如何处理？是否限制多次失约用户？
4. 单用户同时段/单日可约几次？
5. 时段与容量由门店自配还是品牌方统一配？

**归属（第 2 期）**
6. 无门店参数进入时归属给谁？
7. 购物车跨店如何处理？
8. 归属会话有效期多长？

**分账（第 3 期）**
9. 服务商资质与分账权限能否获批？
10. 抽成比例是否在分账上限内？
11. 加盟商是否都有独立营业执照与对公账户？
12. 税务模型是否经会计师确认？

**卡包（第 4 期）**
13. 微信卡券当前政策是否仍支持所需能力？
