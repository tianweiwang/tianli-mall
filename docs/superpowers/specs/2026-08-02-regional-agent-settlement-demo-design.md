# 区域代理结算 Demo 设计

## 1. 背景与目标

当前加盟平台 H5 Demo 已包含消费者端、门店端和品牌方后台，并已演示个人分享分销、会员本金、赠送积分、客户补贴和订单分账。新结算口径要求特色系列、经典系列按以下比例拆分实际支付金额：

- 门店：50%
- 产品方（集团）：35%
- 区域代理商：15%

区域代理商是负责招商、发展和管理加盟门店的区域或渠道主体，不是消费者分享产生的个人分销员，也不是微信支付服务商。

本次目标是在不新增代理商登录端的前提下，通过品牌方后台完整展示“代理档案、门店归属、订单结算快照、模拟品牌分账和代理收益”的业务闭环。

## 2. 范围

### 2.1 包含

- 品牌后台新增区域代理列表和代理详情。
- 门店绑定一个有效区域代理，或标记为集团直营。
- 特色系列、经典系列订单保存代理归属和结算比例快照。
- 门店、订单、分账详情展示代理归属及三方金额。
- 品牌后台展示代理累计收益、待结金额、归属门店和结算流水。
- 模拟分账完成后同步更新代理收益。
- 直营门店、代理停用、积分支付和分账失败的演示状态。

### 2.2 不包含

- 独立代理商登录端。
- 真实微信支付、真实品牌分账、代理商进件或银行卡打款。
- 真实后台接口、数据库和财务凭证。
- 区域代理层级、跨级代理、代理招商奖励或代理提现。
- 修改消费者个人分享分销的绑定关系。

## 3. 核心业务口径

### 3.1 代理归属

区域代理关系绑定在门店主体上，不绑定消费者。一个门店同一时刻只有一个有效代理归属；集团直营门店没有代理档案。

订单支付时保存代理、门店和比例快照。门店后续更换代理或代理停用，不追溯修改历史订单及历史结算记录。

### 3.2 结算模板

有代理的加盟门店：

| 接收方 | 比例 |
| --- | ---: |
| 门店 | 50% |
| 集团 | 35% |
| 区域代理 | 15% |

集团直营门店：

| 接收方 | 比例 |
| --- | ---: |
| 门店 | 50% |
| 集团 | 50% |
| 区域代理 | 0% |

所有模板合计必须为 100%。

### 3.3 结算基数

三方结算只按订单实际支付的现金或会员本金计算。会员折扣订单按折扣后的实际本金拆分，不按商品原价拆分。

例如特色或经典项目原价 100 元，会员本金按 6.6 折支付 66 元：

- 门店：33 元
- 集团：23.10 元
- 区域代理：9.90 元

赠送积分支付不产生现金分账，门店、集团和区域代理的现金分账均为 0，只生成积分消费和服务履约记录。

金额统一以分为单位计算。尾差沿用现有订单分账规则，并保证三方金额之和严格等于结算基数。

### 3.4 适用品类

新比例只适用于特色系列和经典系列。其他服务与商品继续使用其现有 Demo 结算规则，不在本次设计中扩展。

### 3.5 与个人分享分销的关系

区域代理和消费者个人分销是两套独立关系：

- 区域代理 15% 参与订单模拟品牌分账。
- 个人分享佣金 8% 不参与微信品牌分账，继续由集团独立推广预算承担。
- 个人分享佣金不减少门店收入、区域代理收入或客户补贴资金池。
- 品牌后台分别使用“区域代理”和“分销管理”展示两类主体和两套流水。

一笔 5100 元会员本金订单若同时归属区域代理且来自个人分享：

| 项目 | 金额 | 资金口径 |
| --- | ---: | --- |
| 门店收入 | 2550 元 | 订单分账 50% |
| 集团补贴资金池入账 | 1785 元 | 订单分账 35% |
| 区域代理收入 | 765 元 | 订单分账 15% |
| 个人分享佣金 | 408 元 | 集团推广预算另行承担 |

个人分享佣金是订单分账之外的集团费用，因此不能把上述四项相加后解释为订单支付金额的拆分。

### 3.6 与客户补贴的关系

集团 35% 收入进入集团公共补贴资金池。客户每周三返 51 元、最多 100 期的补贴计划仍使用独立负债台账。

5100 元订单中集团 35% 为 1785 元，只能覆盖 35 期、合计 1785 元补贴；100 期共 5100 元，剩余 3315 元由集团公共补贴资金池承担。Demo 不得将单笔 1785 元显示为已覆盖完整 100 期补贴。

## 4. 信息架构

品牌后台侧栏新增“区域代理”，与“加盟门店”“分账流水”“分销管理”并列。

### 4.1 新增页面

#### 区域代理列表

展示：

- 代理名称
- 联系人
- 合作状态
- 固定结算比例 15%
- 归属门店数
- 累计已结收益
- 待结金额
- 查看详情入口

列表顶部展示有效代理数、覆盖门店数和待结金额。代理档案使用确定性的本地种子数据，本次不提供新增、编辑或真实进件操作。

#### 区域代理详情

展示：

- 代理基本档案和合作状态
- 归属门店
- 关联订单
- 结算流水
- 累计已结收益和待结金额

代理详情可进入门店详情、订单详情和分账详情。

### 4.2 扩展现有页面

- 品牌总览：增加代理待结金额及区域代理入口。
- 门店列表与详情：显示代理归属、合作状态和结算模板；代理名称可进入代理详情。
- 订单列表与详情：显示支付时保存的代理快照、结算基数和三方金额。
- 分账列表与详情：显示门店 50%、集团 35% 或 50%、代理 15% 或 0%，并可进入代理详情。
- 分销管理：明确个人佣金由集团推广预算承担，避免与区域代理 15% 混淆。

消费者端不展示代理档案。门店端只在结算明细中看到本店收入及结算说明，不提供代理管理操作。

## 5. 演示数据模型

在现有本地版本化状态中增加以下概念：

- `regionalAgents`：代理档案、状态和联系人。
- 门店代理归属：门店关联代理 ID；直营门店为空。
- 订单结算快照：适用规则、代理 ID、代理名称、三方比例、结算基数和三方金额。
- 代理结算视图：从订单分账记录汇总待结及已结收益，不与个人分销佣金记录复用。

区域代理关系不能复用现有个人分享绑定或分销员档案。代理收益可以从订单结算快照和分账状态派生，避免维护第二套可漂移的金额事实；若页面需要独立流水标识，则流水必须引用原分账记录 ID。

重置演示数据后，代理档案、门店归属和固定示例金额恢复到确定状态。

## 6. 状态与流转

代理收益跟随现有订单分账流转：

```text
待分账 -> 处理中 -> 已完成
                    或
                  分账失败 -> 重新处理
```

- 待分账、处理中和分账失败计入代理待结金额。
- 只有已完成计入代理累计已结收益。
- 重复推进已完成记录不能重复增加代理收益。
- 分账失败保留订单、代理快照和失败状态，不删除流水。
- 重新处理只推进原记录，不生成重复代理收入。

正式上线是否允许重新处理以及失败状态名称应以微信支付接口结果为准；Demo 使用明确的“模拟品牌分账”标识。

## 7. 演示主链路

1. 品牌人员打开区域代理列表，查看华北区域代理的覆盖门店和待结金额。
2. 从代理详情进入其归属门店。
3. 切换消费者端，在该门店购买特色或经典项目并使用会员本金支付。
4. 返回品牌后台，从订单详情查看支付快照和 50% / 35% / 15% 拆分。
5. 打开分账详情，将状态从待分账推进到处理中，再推进到已完成。
6. 返回代理详情，确认待结金额减少、累计已结收益只增加一次。
7. 使用集团直营门店订单验证 50% / 50% / 0%。
8. 使用赠送积分支付验证三方现金分账均为 0。
9. 使用个人分享订单验证 8% 佣金只出现在分销流水和集团推广预算说明中。

## 8. 异常与边界

- 门店无代理：显示“集团直营”，自动使用 50% / 50% 模板，不创建代理结算项。
- 代理停用：禁止绑定新门店；历史门店和订单保留原快照，页面明确显示历史关系。
- 非适用品类：继续使用现有结算规则，不强行套用新比例。
- 积分支付：显示“非现金结算”，现金结算金额为 0。
- 状态重复提交：保持幂等，不重复产生代理收益。
- 本地状态损坏或版本不匹配：沿用现有本地状态恢复机制并恢复固定代理种子数据。
- 品牌分账比例：页面标注“模拟品牌分账，正式上线以微信获批最大分账比例为准”。正式实现必须读取并校验实际 `max_ratio`，Demo 不声称已经获得生产额度。

## 9. 验证范围

### 9.1 单元测试

- 有代理门店按 50% / 35% / 15% 计算且合计等于结算基数。
- 直营门店按 50% / 50% / 0% 计算。
- 会员折扣按实际本金计算。
- 积分支付三方现金分账为 0。
- 非特色、非经典品类不应用新模板。
- 订单保存代理快照，门店后续变更不影响历史订单。
- 已完成分账只增加一次代理已结收益。
- 个人分享佣金不进入区域代理流水和补贴资金池。
- 重置后恢复固定代理、门店归属和汇总数据。

### 9.2 页面与端到端测试

- 区域代理列表、详情及品牌总览入口可访问。
- 代理详情能进入关联门店、订单和分账详情。
- 门店、订单和分账页面能反向进入代理详情。
- 有代理、直营、积分支付和个人分享四条演示链路金额与文案一致。
- 模拟分账完成后，代理待结和已结汇总同步变化且不重复。
- 桌面后台和移动宽度下关键字段、操作按钮不溢出或重叠。

### 9.3 交付检查

- 相关 Vitest 测试通过。
- 生产构建通过。
- 相关 Playwright 链路通过。
- 对应 OpenSpec change 验证通过。

## 10. 成功标准

甲方能够在现有 Demo 中清楚区分区域代理和个人分销，并沿一条连续链路看懂：门店为何归属某代理、特色或经典订单如何按实际支付金额拆成 50% / 35% / 15%、分账完成后代理收益如何变化、直营门店如何回退为 50% / 50%，以及集团补贴资金池和个人推广预算为何是订单分账之外的独立账务口径。
