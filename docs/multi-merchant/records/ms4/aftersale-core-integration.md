# Task7 售后核心整合

2026-10-18，沿 09 原 Task7 唯一执行清单和已采用的合同继续 L2 本地开发。目标仍为通用多商户商城，商品、规格、价格和保存金额复用原能力。本文记录整合决定及验证结果，不增加另一套任务清单，不代表 Task7 验收。

## 本次实施决定

将仓库外已完成源码复核的 Input R2、完整 Facts 和 capture、商业纯计算、统一迁移 R2、文件底层 R2、票据、六命令 Writer、Payment 后继观察、Read19、S2 履约消费者和 16 个履约页面源成套接入当前开发分支。最终结构入口三服务、S2 Projection、Read19 RefundDao 与顾客反馈单行修订覆盖其各自的早期供体；不叠加早期候选造成覆盖。实际 61 件来源与整合前后摘要另存仓库外 `ms4-aftersale-main-integration-r2`。首次预检在产品写入前发现 FulfillmentDao 新增处混入 6 个 CRLF；逐处核为源码换行后，本次只将这 6 处统一为 LF，原已审供体保持，供体和最终源分别记录摘要。

所有数据生产者和消费者共用同 PDO 完整事实；写入沿 Payment → Root → operations → capture → family → logs → actions 固定锁序，结束前 fresh 读取验证。原保存金额、原数量、整数分预算、34 列退款镜像、真实主键和四列无主键日志规则均保持。退货选择与实际验收入库分别保存，不把取消区间作为实际收货。S2 原生分页、count 和状态桶复用一个商业条件；旧消费者与定时任务同时接线。

私有图片沿真实认证请求的 token 指纹、持久文件、18 列绑定和限时 header 票据读取；不复用公开图片 URL。`marketplace.aftersale.enabled` 默认 false，仅约束新申请；存量读取和履约义务不因该开关消失。`private_root` 默认空，后续专用实例必须显式挂载持久私有卷，不回退到临时目录或公开目录。新结构物理校核继续保留，未迁移实例不能伪装成已就绪。

原三端售后申请、审批、分次验收、非空凭证页面仍在外部实现；本次 16 个前端文件是 S2 履约消费页，不将其称为完整售后页面。Task8 三核心另有源码交付，尚不混入本次整合。真实金融、非空历史、HTTP/Worker/页面与发布的原未验责任继续保留；用户已停止的样本不运行。

整合前核当前主分支实际提交、干净状态及各供体来源，按唯一最终路径清单写入，并与最终候选逐字比较。完成后运行 PHP 8.2 语法检查及必要的前端检查；语法、源码复核、构建、SQL 正常链、HTTP、Worker 和实际页面分别记结果。统一迁移必须另在专用新实例执行 check → apply → check → apply；非空私有图和完整售后业务尚须正常链验证。未运行的项目不据源码或构建签收。

履约复测使用独立 detached 工作树 `ms4-source-check` 的实际固定提交 `ec814e74eb93acd18c2f5f69be110c218b47fd52`，只验证该快照；本分支后续售后整合不得冒用旧快照结果。原失败测试记录保持。
