# MS0b：会话状态丢失与世代轮换操作说明

本说明适用于会话状态丢失、Redis恢复了旧会话快照，以及业务数据库恢复可能还原历史账号凭据或身份的情况。任务6只保护正常业务账号修改入口；安装初始化、备份导入及人工SQL不经过这些入口。认证恢复前需要使用新的会话世代，避免继续沿用历史认证状态。

当前交付范围为L2本地实现及独立普通命令检查，尚未部署、执行真实环境轮换或恢复演练。用户要求跳过的恢复、故障、并发及旧令牌拒绝检查继续记为未验证；本说明和普通命令通过不构成完整A29验收。

## 适用范围与命令行为

- 当前v2应用为adminapi和outapi；顾客及客服端仍按各自实现运行。MS1接入merchantapi后须同步核对实例和集成清单。
- MCP使用account/password请求头直接核对当前账号凭据及状态，不消费v2会话；轮换epoch不会替代该入口的凭据核对。涉及账号数据库恢复时，须在集成恢复清单中单独核对这些凭据及状态。
- `AUTH_SESSION_EPOCH` 是所有相关实例共同使用的部署配置，格式为1至128个英文字母、数字、点、下划线或连字符。命令不生成、不写入或自动更新该配置。
- `php think auth:epoch-rotate --old-epoch=<旧值> --confirm` 从当前应用已加载的配置读取新值，要求新旧值不同，再使用独立有界原生Redis连接清理旧世代的 `auth:v2:<旧值>:*`。
- 命令用SCAN分批获取，单次DEL最多200键，输出实际 `deleted_keys: N`，不输出键名、配置密钥、令牌、账号或底层异常原文。当前世代和其他业务键保持。
- 该命令不修改数据库、业务缓存、签名密钥或凭据戳密钥；不能代替入口隔离、配置下发或全实例核对。

## 执行顺序

1. 先隔离adminapi/outapi的登录、访问和刷新入口，暂停可能继续使用旧配置的常驻进程及相关后台认证调用。维护入口应由应用外层控制，以免会话状态本身不可用时仍依赖登录操作。
2. 记录恢复前正在使用的准确旧世代、实例范围和原因；仅保存不含凭据的运维记录。若旧世代无法确认，先核对部署配置及历史发布记录，不能用通配符或猜测替代旧值。
3. 完成另行授权的数据恢复后，为所有相关HTTP实例、CLI任务和常驻worker下发同一新的世代。新值可使用运维端生成的32字节随机数的十六进制文本，与旧值不同；签名密钥和凭据戳密钥保持已有受控配置，不能复制到命令行或报告。
4. 重载或重启需要重新加载配置的实例，清理部署层的旧配置缓存。逐实例确认实际已加载的新世代一致；仅设置Env但没有加载到应用Config不算生效。此时继续保持认证入口隔离。
5. 在应用发布目录运行以下命令，将占位词OLD_EPOCH替换为步骤2记录的准确旧值。示例本身不证明真实配置已下发。

   ```sh
   php think auth:epoch-rotate --old-epoch='OLD_EPOCH' --confirm
   ```

6. 检查原生退出码为0以及 `deleted_keys: N` 输出。N是实际删除数；旧空间已经为空时N=0是正常结果。核对当前世代和业务数据保持，再按已有上线验收程序开放正常重新登录，更新集成清单和运维记录。

使用v2令牌的对外集成方与管理员会需要正常重新登录。实际在用的集成方仍需人工核实并按发布计划通知；本说明不声称已经核实、通知或切换。

## 中断、失败与重跑

非零退出表示未完成。部分旧键可能已经删除，保持新配置及入口隔离，先核对配置和依赖；不能把错误当成功，也不能恢复旧世代来保留历史会话。修复后使用同一个准确旧值正常重跑，命令不会重建旧会话，已删除的键不重复计数。命令本身没有自动重试或补偿。

不得使用FLUSHALL、FLUSHDB、业务全库清空、关闭鉴权或回退至旧会话白名单来恢复认证。回退代码也必须保留MS0a边界和当前世代；业务数据库恢复属于独立授权的数据操作，须说明恢复窗口及后续账号/数据核对，不能由本命令执行。

## 本地验证与尚待证据

独立普通检查使用专用ISO-FULL实例中的正常自有会话：实际think命令注册和帮助、旧世代精确分批清理、已空旧空间重复执行。观察完整安装表、所有其他Redis值与绝对期限及runtime，记录实际退出码和删除数。

没有执行RDB恢复、依赖故障、旧令牌拒绝或并发复现。真实入口隔离、配置下发、全实例重新加载、生产清理、集成通知和恢复后的真实业务验收尚未执行；后续交付报告只列实际证据，不把这些步骤记为通过。
