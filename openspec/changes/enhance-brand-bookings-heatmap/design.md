## Context

已确认的完整设计位于 `docs/superpowers/specs/2026-07-30-brand-bookings-heatmap-design.md`。当前 `Bookings.vue` 直接从本地 Demo 状态中过滤预约并渲染表格，`slotInventory` 已包含日期、门店、服务、开始结束时间、容量和已预约数，可在不增加接口的前提下生成全局热力总览。

## Goals / Non-Goals

**Goals:**

- 默认展示 `state.demoNow` 对应日期的跨门店预约总览。
- 使用实际开放时段，不将不同时长的服务强制切成固定时间格。
- 让热力格选择、关注提醒和明细表保持单一筛选来源。
- 保持现有后台视觉、表格字段和详情抽屉。

**Non-Goals:**

- 周历、月历、排班编辑或容量修改。
- 新业务状态、自动过期或预约状态推进。
- 真实接口、数据库或跨设备同步。
- 其他品牌后台页面重构。

## Decisions

### 用纯选择器聚合热力数据

在 `mock/selectors.js` 中增加纯函数，根据日期、门店和服务筛选生成指标、时段列、门店行、热力格和关注项。页面不在模板中重复跨门店聚合，测试可以直接验证容量、排序和状态口径。

### 横轴使用实际时段并按时间合并

横轴取所选日期全部门店的开始结束时间并集。同一门店、同一时间若配置多个服务，则合并容量和已预约数；选择服务后只保留该服务。无对应时段显示未开放，停用门店整行显示停约。

### 容量热力和预约明细分开筛选

日期、门店和服务影响指标、热力与明细。预约状态和关键词只影响明细，避免筛选已核销记录时改变配置容量。点击热力格只增加门店、日期和时段过滤，不修改业务数据。

### 通过种子版本升级补充今日数据

保留全部现有示例记录，在 `state.demoNow` 日期新增可重复的时段和预约记录，并递增演示状态版本。已有浏览器状态会走现有版本不匹配恢复流程，不引入迁移逻辑。

## Risks / Trade-offs

- 门店和时段较多时矩阵会横向变宽，因此滚动限制在矩阵内部，并保持门店信息可辨识。
- 同时段多个服务被聚合后不能在一个格内逐项比较，品牌方可使用服务筛选拆分查看。
- 状态筛选不改变顶部指标，这一口径更稳定，但必须通过筛选摘要明确明细与总览的范围差异。

## Verification

- Vitest 验证默认日期、时段并集、服务聚合、状态判定、空状态和种子数据一致性。
- 组件测试验证键盘可选格、未开放格和选择事件。
- Playwright 验证热力格下钻、清除选择、详情抽屉、1280×800 与 1440×900 无页面级溢出。
- 运行生产构建和 `openspec validate enhance-brand-bookings-heatmap`。
