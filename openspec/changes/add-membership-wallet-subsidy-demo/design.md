# Design: 会员储值与补贴 Demo

## State Ownership

会员领域使用独立的 `memberSelectors.js` 和 `memberTransitions.js`。所有余额变化通过 transition 完成，并同时写入资产流水。页面只读取选择器结果和提交明确业务动作。

现有积分账户迁移为按 `customerId` 隔离的账户。下单奖励、预约奖励和储值赠送的 10200 分进入同一客户积分余额，流水保留来源。消费者切换时不复制或改写其他客户资产。

## Membership Boundary

510 元会员卡生成六项权益，并提供服务 6.6 折与商品 8.5 折。5100 元储值生成 5100 元本金、10200 分积分和服务 6.6 折，但不生成会员卡的礼品、项目权益或代金券。

礼品、600 元项目权益和代金券本期只生成和展示状态；实际领取、核销和抵扣不在本期范围。

## Settlement

门店只对已核销且属于当前门店的预约结算。储值本金按项目原价 66% 扣除，积分按 `1 元 = 1 积分` 的原价扣除。每个预约只能结算一次，余额不足时不能留下部分余额、流水或消费记录。

商品订单只有 510 元会员享 8.5 折。使用储值本金支付时，实际本金扣款进入补贴累计；其他支付来源不累计。

## Subsidy

每位客户符合条件的储值本金累计消费达到 5100 元时，只创建一份 100 期补贴计划。品牌使用固定周期标识执行本周批次，每个有效计划每期增加客户补贴余额 51 元。同一周期重复执行不得重复到账。

## UI

客户个人中心连接会员中心与资产中心；门店预约详情提供项目结算抽屉；品牌新增会员运营页面，以页签展示会员、开卡储值、消费、补贴计划和发放记录。

## Verification

Vitest 覆盖所有资金公式、客户隔离和幂等边界。Playwright 分别在移动客户视口和桌面管理视口执行开卡储值、门店结算、品牌发放和客户到账路径。
