## 背景

检测设备是固定绑定到门店的资产，创建任务后不应再经过任务二维码和设备领取。品牌端需要在既有运营聚合数据之外查看已发布报告的脱敏明细，但不能获得医疗、影像或编辑能力。

## 决策

### 自动绑定与状态机

预约检测和现场建档沿用原有顾客、门店、预约及授权校验。校验通过后，从任务所属门店固定设备中查找 `online` 设备；Demo 种子保证可创建任务的门店至多命中一台在线设备。命中后任务直接保存 `deviceId` 并以 `ready` 创建。

正常状态严格为 `ready -> measuring -> awaiting-review -> completed`，页面文案依次为待检测、检测中、待确认、已完成。新结果只允许在 `measuring` 或补充数据用的 `review-required` 状态接收，且载荷设备必须等于任务自动绑定设备；重复结果仍优先按结果流水幂等返回。删除任务二维码、领取操作及 `waiting-device`、`claimed` 的可见流程。

门店没有在线设备时，创建动作失败并提示“本店检测设备当前不可用”；预约入口和现场入口都必须向操作员展示该原因，且不得写入部分任务。设备在任务创建后离线时，保留同一任务和设备，在 `retrying` 后恢复到 `measuring`，不重新绑定或创建任务。门店任务详情统一使用选择器提供的脱敏手机号，不直接读取顾客原始字段。

### 异常结果边界

不完整载荷进入 `review-required`，补充后仍用同一任务和绑定设备回传。设备结果流水用于重复回传去重，已接收结果不再生成新报告。跨店设备或同店非绑定设备结果进入隔离状态，不改变任务归属且不得生成正式品牌记录；其他非接收状态的新结果直接拒绝且不追加原始提交。

### 品牌已发布记录

品牌记录选择器仅从 `reportStatus === 'published'` 的报告生成正式行。待确认和待复核任务继续保留在既有运营聚合指标中，筛选不改变这些全局统计。

记录表支持门店、单个检测日期、报告编号或顾客姓名关键词筛选。表格展示报告编号、顾客姓名和脱敏手机号、门店、固定设备、检测时间、肩高差、骨盆倾斜、颈前倾角、不适评分及查看动作。手机号脱敏在选择器中完成，不允许输出连续 11 位手机号。

右侧抽屉展示同一报告的顾客、门店、时间、四项指标、相对上次和首次报告的变化、设备名称/型号/软件版本、报告版本和已发布的非医疗建议。没有可比较历史时明确显示“暂无对比”，不得使用 0 替代。抽屉不展示检测影像、完整手机号、指标编辑、报告操作或医疗结论。

### 确定性演示数据

保留 `ASR202607301001` 与 `ASR202607301002` 两份既有报告及其数值；补充另一家门店的已完成任务和已发布报告，支撑跨店筛选。递增 Demo 版本，使旧本地状态依据既有恢复机制替换为新种子；重置仍恢复相同数据。新种子不含 `waiting-device` 或 `claimed` 状态。

## 实现边界

变更局限于本地 H5 Demo 的评估领域种子、状态转换、选择器、门店页面、品牌页面和相关测试。不接入真实硬件、厂商或远程 API、数据库、CRMEB 正式接口；不实现多设备调度、远程控制、设备配置或校准。不修改公共二维码编解码器和消费者预约核销二维码。

## 验证策略

以领域单元测试覆盖自动绑定、状态机和四类异常，以选择器测试覆盖已发布记录、脱敏和对比，以页面测试覆盖门店动作、品牌筛选及抽屉。通过 Playwright 验证创建到品牌查看的完整流程和二维码回归，再运行完整单元测试、生产构建及 OpenSpec 校验。
