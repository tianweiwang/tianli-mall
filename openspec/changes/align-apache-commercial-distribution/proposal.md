## Why

仓库根 `LICENSE` 和 `README.md` 声明 Apache-2.0、免费商用、无隐藏费用或功能限制，但应用内许可、源码头、安装器、后台商业授权接口、授权购买页面、品牌强制兜底和部分在线升级流程仍实施额外限制或自动向 CRMEB 服务发送站点信息。发行声明、实际代码和安装数据不一致，既会误导部署者，也会让默认离线部署产生不必要的外部请求。

本变更以项目所有者确认的 Apache-2.0 发行规则为准，删除冲突限制，同时保留 Apache-2.0 要求的来源归属、普通安全鉴权、本地品牌配置和离线升级能力。

## What Changes

- 统一根目录、应用目录、安装器和项目自有源码头的 Apache-2.0 许可表述，保留原版权和作者归属。
- 删除商业授权查询/申请服务、后端路由、首页自动探测、前端 API 和购买/授权 UI。
- 将“商业授权”页面改为只使用本地环境诊断和站点品牌接口的“系统信息”页面，并保留菜单 ID `605` 的角色关联。
- 将 CRMEB 专用版权配置键和前端符号中性化，保留 `/copyright` 响应契约；空配置不再显示 CRMEB 文案、链接或图片。
- 删除未引用且会同步站点信息的旧升级客户端；官方远程升级改为部署配置显式启用、默认关闭、惰性认证且仅使用 HTTPS。
- 保留本地跨版本升级、备份和回滚，使其不依赖官方远程升级门禁。
- 清理安装 SQL、多语言文本、文件树、MD5 清单和升级内嵌清单中的授权残留，并提供只影响明确授权/品牌/菜单记录的幂等存量迁移。
- 重建管理端和可复现的商城端发布产物，删除不再被入口引用的旧哈希资源。
- 增加许可/授权否定清单、默认无外联、迁移幂等、品牌空状态和本地升级回归测试。

## Capabilities

### New Capabilities

- `commercial-distribution-compliance`: 使许可文本、运行时授权行为、品牌展示、安装数据和可选官方升级符合项目声明的 Apache-2.0 商业发行规则。

## Impact

- 后端：`Common`、商业授权服务/路由、品牌配置消费者、在线/跨版本升级服务和配置。
- 管理端：首页、系统信息路由与页面、在线升级页、品牌组件、登录/客服页面、API 包装和构建产物。
- 商城端：版权 API 包装和所有 CRMEB 图片/文案兜底消费者，以及可复现的 H5/小程序产物。
- 安装/升级：安装协议、初始化 SQL、语言包、文件树/MD5 清单、内嵌升级清单和一份幂等存量迁移。
- 数据：只删除授权元数据、重命名品牌键并原地更新菜单 ID `605`；商品、订单、用户、上传文件和示例数据不变。
- 部署：新增 `UPGRADE.OFFICIAL_REMOTE_ENABLED=false` 示例配置。启用官方远程升级是部署者的显式操作。

## Assumptions

- 项目所有者有权将当前发行版按根目录 Apache-2.0 规则发布；本变更不独立裁定上游权利冲突。
- `eb_system_role.rules` 等角色关联以菜单 ID 为主，因此保留菜单 ID `605` 是最小权限迁移。
- 远程升级不是商城核心运行依赖；默认关闭不会影响下单、支付、商品、用户或本地升级。
