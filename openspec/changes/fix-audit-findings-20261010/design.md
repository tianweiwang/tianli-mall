# Design

## Backend permission and upload

SystemRoleServices::verifyAuth 对已登记但不授权的规则抛 AuthException，而非 return false（调用方忽略返回值）。保持既有超级管理员、logout/menuslist、未登记路由及 CRUD 豁免；空方法权限列表使用安全默认值。异常保留现有业务 400 协议，因为后台对业务 403 有文件密码专用含义。

扫码上传要求缓存与请求凭证均为非空字符串，再用 hash_equals 比较，拒绝 PHP 宽松比较和空缓存绕过。验证必须早于附件服务实例化。真实控制器/中间件回归使用内存依赖，不产生真实文件上传。

## Payment and coupon transactions

余额支付在同一事务内按订单、账户顺序 SELECT FOR UPDATE；重新校验订单状态、账户余额。锁内的账户余额用于扣款和流水结余，锁内订单用于支付成功处理。覆盖商品与会员单，防止同单重复扣款；保留余额不足返回协议。优先用现有 selectModel()->lock(true)，不扩大修改到所有 BaseDao 数值操作。

### A3 补充：同一余额的其他写入者

实施前真实 MySQL 回归确认 100 元余额两笔 80 元订单都支付成功，余额只减至 20；两笔 40 元订单余额错误为 60。相关写入者检查进一步发现退款使用 BaseDao::bcInc、充值/佣金转入/后台调额/注册奖励直接读取旧余额后绝对更新，也可能覆盖已加锁的支付。因此 A3 扩展到已定位的同一 now_money 写入路径：所有计算余额和对应流水的读取均须位于共同的账户行锁保护内，事务原子提交。锁顺序优先业务订单再账户；单账户调额先锁账户。BaseDao::bc 可在自身事务内锁行读取，保留精度、返回 bool、余额不足返回 false 约定并兼容外层事务。直接写入者也须持锁，不以仅修通用 bc 代替。

不改充值金额、退款规则和佣金规则，不触发真实外部支付；测试替换事件/支付网关副作用。增加支付并发充值/退款/后台调额的隔离回归，以及相应流水/异常回滚验证。该补充只解决已确认的余额覆盖原因，不扩展支付网关回调协议设计。

收尾检查补充同一问题的剩余本地读改写入口：移动端商家调额、抽奖余额消耗和现金奖励也须在账户锁内重新取余额，领奖状态与记账同事务并重查，避免重复领奖。范围仍为本地余额计算写入；LoginServices::remoteRegister 接收外部系统余额作为绝对值同步，没有从本地旧余额计算，不改变其跨系统数据同步协议。数据库回归替换外部通知/队列，不声称外部事件可随数据库回滚撤销。

优惠券试算只读；订单创建事务内核销。DAO 原子条件包含券 ID、uid、status=0、is_fail=0 和有效期，受影响行数必须为 1。地址校验在事务前无副作用；库存及后续失败由同事务回滚。其他 useCoupon 调用点需一起核实协议。

## Frontend

从已核实的备份前提交 3e2a1a158149dbf35b4438f5d317b6ec2316e166 恢复 template/admin/src/vendor 下 Blob.js、Export2Excel.js、newToExcel.js；记录 Git blob/摘要验证，确保忽略规则不会再排除项目源文件。构建前检查关键依赖完整性，使用隔离 Node 22，不更改系统默认 Node。

小程序和 App 通过 VUE_APP_API_URL 配置服务 origin；共用校验模块拒绝缺失、非法协议、路径/凭证、官方 demo 回退。生产 HTTPS，开发仅显式本机/局域网 HTTP。vue.config.js 根据 UNI_PLATFORM 在构建阶段校验，app.js 在运行边界兜底；H5 同域逻辑不变。未收到真实域名时提交配置示例和明确报错，不猜测域名。

用户已选择先连接本地：开发默认 http://127.0.0.1:8011，允许 .env.development.local 覆盖同一局域网地址；不改变当前 PHP 服务监听。生产仍要求显式 HTTPS origin。真实设备和正式域名验证在实际环境可用后进行。

安装 HBuilderX 后实际 MP 编译发现：其 Vue CLI 的 context 为编译器目录，不会读取业务项目的 .env。构建校验前从项目目录按 .env.<mode>.local、.env.<mode>、.env.local、.env 的优先级补读 VUE_APP_API_URL，复用编译器已有 dotenv 解析器；显式环境变量（含空值）优先，不加载其他变量、不引入默认生产域名。通过现有 Vue CLI DefinePlugin 把已加载地址注入目标包，运行端继续共用校验。测试需覆盖不同工作目录、local 覆盖、外部变量优先、生产不读开发文件，并核实实际 MP/App 编译结果。

后续构建预览保持独立输出目录。HBuilderX 的 publish web 要求账号登录；可使用已安装的官方 Vue2 编译器执行本地 uni-build（不改登录检查、不调用云发布）。补齐列表稳定 id key，并将 Sass 声明调整为 Mac ARM 已实际使用的 dart-sass，不改业务和样式。

request.js 的业务状态 402 保留现有维护提示并 reject。测试执行真实模块，验证成功、登录失效、维护和普通错误均结束 Promise；浏览器使用真实 uni UI 和 mock 网络验证消费者 loading 清理，不切换真实维护开关。

## Theme schema and legacy DIY

先核实仓库/备份安装 SQL 是否存在 canonical theme_module 定义。若无，按现有模型和服务的 id/type/data 契约建立最小 InnoDB/utf8mb4 表，并记录来源。迁移默认只检查，显式 --apply 才新建；已存在时校验结构而非跳过错误，绝不覆盖既有表。只提供安全的空表回滚条件，不删除有数据的表。

v1 PublicController::getDiy 调用现有 DiyServices::getDiy，保留路由参数与 JSON 包装；对默认页和指定 ID 验证与 v2 一致。

## Recovery

源码可逐项回退；恢复 vendor 源文件不影响业务数据。迁移只新增空表且不改旧表，回滚仅在新增表仍为空并经明确执行时删除。并发测试隔离库使用唯一名称和清理保护。前端构建产物先在临时位置验证，不覆盖 upload 或其他恢复文件。

最终 H5/后台产物完成独立浏览器预览后，将其提供到现有本地 8011 预览。仅对产物中列出的文件按 H5→public、admin dist→public/admin 映射更新，拒绝符号链接目标和后端/上传路径；每个被覆盖文件先保存备份与 SHA256，新文件登记为新增。使用同目录临时文件再原子替换，不删除旧资源。比较更新前后 uploads 全部文件与 PHP 入口摘要；核实 HTTP 返回内容与新构建一致，再运行实际服务的浏览器回归。失败按清单还原旧文件、删除本次新增文件。该操作仅修改本机静态预览，不触及数据库、服务监听或远程部署。
