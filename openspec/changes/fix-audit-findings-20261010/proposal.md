# 修复 2026-10-10 审计确认问题

## Outcome and scope

用户要求“全部修复”。范围为本次复审确认的 8 项问题，以及之前确认的 v1 DIY 接口异常：后台角色越权、扫码上传空凭证、余额并发扣款、后台导出源码遗漏、优惠券提前核销、主题组件缺表、小程序/App 指向官方演示站、维护状态请求不结束、旧版 DIY 调用不存在的方法。

现有授权覆盖设计、实现和本地验证。保留本次开始前已有的 Docker 文档/脚本修改和恢复的 public/vendor/runtime；不部署远端、不修改真实订单/余额/优惠券，不扩展到已撤回的核销权限、token 类型和库存假设。当前项目未启用 Git auto-sync。

## Acceptance

- A1：已登记的后台接口对无对应方法/规则权限的角色抛出异常，中间件不执行下一处理器；原有超级管理员和明确豁免保持工作。
- A2：空、缺失、过期、错误类型或不匹配的扫码上传凭证在附件服务实例化前被拒绝；有效凭证仍可调用上传。
- A3：同账户并发余额支付不能超支或覆盖扣款；相关充值、退款、佣金转入、后台/移动商家调额、注册奖励及抽奖余额读改写共同加账户锁，流水记录锁内真实余额；重复支付/领奖和事务失败不会重复扣款/入账或部分提交，含会员订单。
- A4：3 个导出依赖文件恢复为备份前精确版本，源码缺失检查可发现遗漏；在支持的 Node 版本上构建后台成功。
- A5：订单试算无核销副作用；只有实际创建订单事务内可原子核销本人的有效未使用券；后续失败回滚，并发争用只有一个成功。
- A6：提供可检查、幂等、拒绝不兼容既有结构的 theme_module 迁移；只新增空表；服务列表正常，隔离库增删改查验证通过，原业务表不改动。
- A7：MP/App 必须显式配置后端 origin，生产使用 HTTPS；缺配置在构建时失败且无演示站回退。用户已选择开发先连本地 http://127.0.0.1:8011，H5 保持当前域名。正式域名及完整平台/真机验收未完成时单列说明。
- A8：维护状态 402 显示提示后 reject，调用方 catch/finally 可清理 loading；保留其余请求状态行为，并在浏览器 mock 网络验证。
- A9：v1 DIY 使用有效服务方法；只读 HTTP 验证返回成功并与相同参数的 v2 数据一致。
