## 背景

需求清单中的十个模块，预约、下单、核销、展示、结算已有完整页面和本地状态；分享仅有预约二维码下载。推荐、分销、积分、提现完全缺失。本变更在既有 Demo 架构内补齐五个增长模块，全部使用确定性本地种子和 localStorage 假数据，不接真实接口。

## 决策

### 积分

种子提供 `pointsAccount`（余额、累计获取、累计使用）和 `pointsLedger`（类型、标题、积分、发生时间、变动后余额）。下单支付按实付金额每 100 分奖励 1 积分；预约创建固定奖励 100 积分。消费者积分中心展示余额、规则、兑换项和明细；兑换操作写入扣减记录并在余额不足时拒绝。

### 推荐

种子提供推荐码、单笔奖励金额（按金额百分比或固定值）、邀请记录列表（待首单、已首单、已奖励）。推荐有礼页面展示邀请二维码、复制邀请链接、奖励规则和邀请记录；模拟邀请好友动作追加一条待首单记录。

### 分销

种子提供当前演示分销员档案（等级、佣金比例、累计/已结算/待结算佣金）和佣金记录（关联订单、顾客、金额、状态）。消费者分销中心展示佣金汇总、佣金明细和团队规模；分销提现走统一提现申请。品牌分销管理展示分销员档案、佣金汇总和佣金明细。

### 提现

统一 `withdrawalRequests` 记录，区分 `store` 与 `distributor` 两种主体，状态为 `pending -> processing -> completed` 或直接 `rejected`。门店可提现余额 = 已完成结算收入 - 已提交（非拒绝）提现；分销员可提现余额 = 已结算佣金 - 已提交（非拒绝）提现。门店端提现管理提供申请表单与记录列表；品牌端提现审核提供筛选、通过和驳回操作。

### 分享

种子提供分享记录（渠道、内容、访问、转化订单、时间）。分享中心按门店/商品/预约三种内容提供演示文案、二维码和“模拟分享”动作，动作追加回流记录。品牌分销管理顶部汇总展示分享访问与转化，形成推荐→分享→分销的演示串联。

### 数据一致性

新增 `customer` 与 `activeCustomerId` 字段，使预约和积分等消费者记录归属于同一演示顾客。所有新模块读取同一份本地状态，`demoStore.reset()` 恢复固定种子；DEMO_VERSION 递增使旧本地数据自动替换。

## 实现边界

只修改本地 H5 Demo 的种子、状态机、选择器、页面、路由、菜单和相关测试。不接入真实支付、实名、风控、短信或 CRMEB 正式接口；提现与积分均为演示假数据，不做真实资金操作。

## 验证策略

用领域单元测试覆盖积分奖励与扣减、推荐追加、分销佣金汇总、提现申请校验和审核状态机；用页面测试断言三角色新页面可加载并展示关键数据；运行完整 Vitest、生产构建和 OpenSpec 校验。
