## 背景

品牌目录由两类商品构成：到店服务项目（按系列、时长、单次/疗程定价）与实物商品（按单位与规格售卖）。现有 Demo 种子只有 3 款电子产品和 3 个占位服务，无法承载甲方演示。本变更把种子替换为真实品牌目录，并在消费者端、品牌端、门店端提供双业态展示。

## 决策

### 实物商品目录

用 IGOOD 维养系列 11 款产品替换演示电子产品，字段包括系列（维养系列）、分类（营养补充/养护护理/家居理疗/寝具/健康穿戴/理疗器械）、单位（瓶/桶/盒/个/张/台/双）、统一售价、规格与状态。订单、直播挂载商品、分类销售统计同步引用新产品，保持演示数据自洽。

### 服务项目目录

服务扩展为六大系列：评估系列（保留体态健康评估、脊柱舒缓体验、家庭健康咨询，供复评预约与既有预约链路使用）、传统系列、特色系列、经典系列、精品系列、定制系列。每个服务包含时长、单次价、疗程价、疗程规格（次/套）；定制系列使用报价模式，展示"起价"并引导到店定制。

### 双履约路径

服务走"列表 → 详情 → 预约"链路，预约按钮带 `serviceId` 直达 BookingCreate 并预选项目；商品保持"列表 → 详情 → 加购 → 下单"链路。消费者首页提供"门店项目 / 健康好物"双入口，底部导航首页高亮覆盖新路由。

### 后台目录管理

品牌端与门店端 `Products` 页面改为服务/商品双 Tab：服务 Tab 支持按系列筛选并展示时长、单次价、疗程价；商品 Tab 保持现有表格并按分类/系列筛选。菜单与页面标题同步改为"目录管理"（品牌）与"服务与商品"（门店）。

### 档期数据

保留既有档期，并为传统/特色/经典/精品/定制中的代表服务在两家营业门店补充演示档期；品牌预约热力按时间段聚合，新档期会扩大容量汇总，相关断言同步更新。

### 旧数据迁移

`DEMO_VERSION` 从 6 升至 7，旧本地数据自动被新种子替换；版本号不回退。

## 实现边界

只修改本地 H5 Demo 的种子、选择器、页面、路由、菜单与测试。不修改 CRMEB 正式代码、接口、数据库或容器；服务价格、疗程与定制报价均为演示假数据，不产生真实交易。

## 验证策略

新增领域单元测试覆盖服务系列选择器、目录概览与档期可用性；页面测试断言消费者服务列表/详情、品牌与门店双 Tab 页面可加载并展示关键数据；E2E 冒烟覆盖服务浏览 → 详情 → 预约、品牌目录双 Tab。最后运行完整 Vitest、生产构建、E2E 与 OpenSpec 校验。
