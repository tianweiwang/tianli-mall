## 背景

需求清单中的十个演示模块已覆盖预约、推荐、分销、结算、展示、积分、提现、分享、下单和核销，但直播模块缺失。原 CRMEB 商城具备直播与直播商品能力，甲方演示时需要看到"直播带货 → 进店下单"的增长链路。本变更在既有 Demo 架构内补齐直播模块，全部使用确定性本地种子和 localStorage 假数据，不接真实推流或第三方直播平台。

## 决策

### 数据模型

种子提供 `liveRooms` 场次记录，字段包括门店、标题、主播、状态（`live` / `upcoming` / `ended`）、开播/结束时间、观看数、点赞数和挂载商品 ID 列表。`sequence.live` 提供场次自增 ID，门店创建新场次后继续递增。

### 状态机

`bumpLiveStats` 仅允许对 `live` 状态场次累加观看与点赞，其他状态抛出错误并保持数据不变；`createLiveRoom` 仅允许 active 门店创建，新场次固定为 `upcoming` 状态。两个动作都会写入本地活动流水，便于回放演示操作轨迹。

### 三角色授权范围

- 消费者只能查看当前门店的场次列表与直播间，直播商品可直接加购，进入直播间前无需真实账号。
- 门店端只能查看本店场次与指标，并创建演示场次、挂载商品。
- 品牌端跨门店查看全部场次汇总、状态筛选与观看/点赞数据，不做真实开播或推流控制。

### 旧数据迁移

`DEMO_VERSION` 从 5 升至 6，本地已存在 v5 演示数据的浏览器会自动替换为新种子并带出直播场次。版本号是本地演示数据迁移的既有机制，不回退。

### 直播间呈现

直播画面为本地模拟 UI（状态徽标、模拟画面、点赞/模拟进入按钮），不接入真实视频推流、播放、弹幕、礼物或第三方直播平台。回放场次展示"已结束，可回放"提示，预告场次展示开播时间。

## 实现边界

只修改本地 H5 Demo 的种子、状态机、选择器、页面、路由、菜单和相关测试。不修改 CRMEB 正式前台、后台、接口、数据库或容器运行时；不接入真实支付、实名、风控、短信、直播平台或远程 API。

## 验证策略

用领域单元测试覆盖种子与选择器、直播数据累加、创建场次与停用门店拒绝；用页面测试断言三角色直播页面可加载并展示关键数据；用 E2E 冒烟覆盖消费者进直播间 → 点赞/进入 → 门店管理 → 品牌运营。最后运行完整 Vitest、生产构建和 OpenSpec 校验。
